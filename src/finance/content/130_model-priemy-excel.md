# Приёмы Excel для моделей: таблица данных, сценарии, блоки, лестница, добор кредита
short: Data Table, сценарии на CHOOSE, INDEX + MATCH, лестница амортизации, football field, револьвер с циклической ссылкой

> **Суть.** Шесть приёмов покрывают большую часть задач финансового моделирования: таблица чувствительности (Data Table), переключатель сценариев, блоки однотипных объектов, лестница по годам ввода, диаграмма «футбольное поле» и добор кредита с циклической ссылкой. Каждый приём разбирается на мини-примере с условными числами; общие правила модели, цвета и горячие клавиши — в [Финансовая модель в Excel](#learn/excel).

> **За минуту.**
> 1. Data Table (таблица данных): оси задают числами, на том же листе, что и входные ячейки; в углу стоит ссылка на результат.
> 2. Сценарий выбирается списком, превращается в номер, а в драйверах стоит `CHOOSE(номер; база; позитив; негатив)`.
> 3. Однотипные объекты хранят блоками с именованными массивами и читают через `INDEX` + `MATCH`.
> 4. Амортизация и график долга — лестница: строки по годам ввода, колонки по годам.
> 5. Мини-тест показал ловушку: ошибка в формуле скрыта, пока вход и множитель совпадают по значению. Модель проверяют разными числами.

## Как устроен учебный файл

Файл состоит из листов-тренажёров. Каждый лист показывает один приём на мини-примере, под таблицей лежит инструкция по шагам. Раскладка листов одинаковая: название строки, техническая колонка (Tech), единицы измерения (UoM, unit of measure), затем годы. Данные условные: выручка 100, рост 10%, выплата 75% прибыли в дивиденды. Два листа «Bonus» посвящены финансированию: на первом нет циклической ссылки, на втором она есть.

| Лист | Приём | Где нужен в модели |
|---|---|---|
| **Sensitivity** | таблица данных (Data Table) | чувствительность IRR, EV, цены |
| **Scenarios** | список + CHOOSE | базовый, позитивный, негативный сценарии |
| **Blocks** | именованные массивы, INDEX + MATCH | несколько однотипных объектов |
| **Stairs, Capex** | лестница по годам ввода | амортизация, графики долга |
| **Football field** | составная линейчатая диаграмма | итог оценки диапазонами |
| **Financing** | баланс через револьвер, циклическая ссылка | добор и погашение кредита |

Названия листов в файле — с опечаткой в слове Sensitivity (сверить).

## Мини-модель инвестора

Все приёмы разбираются на одной задаче: инвестор покупает долю в компании по мультипликатору P/E (price to earnings, цена к прибыли), получает дивиденды и продаёт долю через пять лет по P/E выхода.

```f
Вложения = прибыль × P/E входа
IRR = XIRR(потоки; даты)
CoC = (дивиденды + выход) / вложения
```

IRR (internal rate of return) — внутренняя норма доходности. CoC (cash-on-cash) — кратность вложений: сколько денег вернулось на единицу вложенного. Потоки: минус вложения на входе, ежегодные дивиденды (выплата 75% прибыли) и выручка от выхода в конце. Выручка растёт на 10% в год.

Пример. Прибыль 10 × P/E 6 = вложения 60. Через пять лет прибыль 16,1, выход 16,1 × 6 = 96,6, дивиденды за период 50,4. Итог: IRR 23,7%, CoC 2,45x.

## Таблица данных (Data Table)

Таблица данных пересчитывает результат модели для сетки значений двух входов. Здесь это вход и выход по P/E, сетка 5×5 от 4x до 8x:

| Вход \ выход P/E | 4x | 6x | 8x |
|---|---|---|---|
| **4x** | 30,6% | 37,3% | 42,8% |
| **5x** | 23,0% | 29,6% | 34,9% |
| **6x** | 17,3% | 23,7% | 28,9% |
| **7x** | 12,8% | 19,1% | 24,2% |
| **8x** | 9,1% | 15,3% | 20,3% |

Это фрагмент таблицы. Базовая точка (вход 6x, выход 6x) даёт 23,7%. Чем дороже вход, тем ниже доходность. Вторая таблица того же размера считает CoC.

**Порядок действий:**
1. Значения осей вставить числами, а не ссылками на модель.
2. В левый верхний угол поставить ссылку на результат (IRR).
3. Выделить всю таблицу вместе с осями и углом.
4. Меню Data → What-If Analysis → Data Table: Row input — входная ячейка для значений по горизонтали, Column input — для значений по вертикали.
5. Если таблица пустая, нажать F9.

В примере Row input — P/E выхода (ячейка J14), Column input — P/E входа (ячейка E14). Правила файла: оси не ссылаются на значения модели, входные ячейки лежат на том же листе, что и таблица. Причина: Data Table подставляет значения оси во входную ячейку. Если ось ссылается на модель, подстановка меняет саму ось, и результаты искажаются. Таблица работает только в Excel: другие программы могут её не пересчитать (сверить).

## Выбор сценария без кода

Сценарий выбирается из списка и превращается в номер, который читают формулы драйверов.

1. Data → Data Validation → List: Base case; Positive case; Negative case.
2. Рядом формула номера: `=IF(D7="Base case";1;IF(D7="Positive case";2;3))`.
3. В каждом драйвере: `=CHOOSE($C$7; база; позитив; негатив)`.
4. Проверка: сменить сценарий и сравнить IRR и CoC.

Альтернатива — переключатель на вкладке Developer (Form Control), значение которого связывают с ячейкой C5. Файл рекомендует список: формат файла не меняется, книга не тяжелеет.

| Параметр | Base | Positive | Negative |
|---|---|---|---|
| **Рост выручки** | 10% | 20% | 0% |
| **Маржа чистой прибыли** | 15% | 20% | 5% |
| **Доля дивидендов** | 75% | 100% | 0% |

Три параметра — три формулы CHOOSE, номер сценария хранится в одной ячейке. Строки сценариев лежат под моделью блоком «Inputs», а в драйверах стоят только формулы CHOOSE, поэтому расчёт читается без переключения.

## Ловушка: ошибка, скрытая совпадением

Все пункты этого раздела — сверить.
- Прибыль в обоих листах считается как выручка × рост, а должна быть выручка × маржа.
- В Sensitivity рост и маржа равны 10%, поэтому ошибка не видна.
- В Scenarios маржа 15% не используется: смена маржи не меняет прибыль.

Правило: модель тестируют разными значениями, а не одинаковыми. Меняйте каждый вход отдельно и смотрите на выход.

## Блочная модель: INDEX + MATCH

Блоки нужны, когда в модели несколько однотипных объектов (школы, магазины, проекты) с одним набором показателей. Пример файла: четыре объекта по четыре показателя (число клиентов, выручка и расходы на единицу, постоянные расходы).

1. Ввести данные блоками по объектам.
2. Выделить блок, Ctrl+Shift+F3 → «Right column»: имена массивов (pupils, revenue, var_costs, fix_costs).
3. Номер объекта: `=MATCH(имя; список имён; 0)`.
4. Значение: `=INDEX(массив; ключ; MATCH(год; строка годов; 0))`.
5. Скопировать блок и заменить `$C$5` на `C5` (Ctrl+H), чтобы ссылка двигалась вместе с копией.

Расчёт объектов: объект 1 — 10 клиентов × 2 = выручка 20, расходы 10 × 2 + 5 = 25, прибыль −5; объект 2 — выручка 40, расходы 25, прибыль +15.

## Лестница амортизации

Лестница — таблица, где строки обозначают годы ввода (когорты), колонки — календарные годы.

```f
Стоимость(t) = CAPEX(t) + стоимость(t−1), пока не списана
Амортизация(t) = −стоимость(t−1) × ставка
Остаток = MAX(стоимость + накопленная амортизация; 0)
```

CAPEX (capital expenditures) — капитальные затраты. Амортизация начинается в год после ввода. Выбор объекта (три объекта с CAPEX 1 000 / 2 000 / 3 000 и ставками 20 / 25 / 30%) делается номером в ячейке через `INDEX`.

Пример. CAPEX 1 000 в год, ставка 20%: каждый год списывается по 200 с каждого годового транша, срок списания пять лет.

| Год | Первоначальная стоимость | Амортизация | Остаточная |
|---|---|---|---|
| **2019** | 1 000 | 0 | 1 000 |
| **2020** | 2 000 | −200 | 1 800 |
| **2021** | 3 000 | −400 | 2 400 |
| **2022** | 4 000 | −600 | 2 800 |
| **2023** | 5 000 | −800 | 3 000 |
| **2024** | 5 000 | −1 000 | 3 000 |
| **2025** | 5 000 | −1 000 | 3 000 |

С шестого года первый транш списан, и модель выходит на устойчивые 1 000 амортизации. На листе Stairs подписи итогов содержат опечатку «Total initail value» (сверить).

## Football field: диапазоны оценки

Football field («футбольное поле») показывает результат оценки диапазонами по каждому методу на одной оси. Для графика нужна таблица «минимум, разница, максимум»: ось строит отрезок как минимум плюс длину.

| Метод | Мин. | Макс. | Разница |
|---|---|---|---|
| **EV/EBITDA** | 120 | 200 | 80 |
| **P/E** | 100 | 170 | 70 |
| **DCF (Gordon), ±10%** | 135 | 165 | 30 |
| **DCF (мультипликатор выхода), ±10%** | 171 | 209 | 38 |

EV (enterprise value) — стоимость предприятия; EBITDA — прибыль до процентов, налогов и амортизации; DCF (discounted cash flow) — оценка по дисконтированным потокам; Gordon — модель терминальной стоимости с постоянным ростом. Единицы в файле не указаны. Точка DCF — 150 и 190, границы = точка × 0,9 и × 1,1; допуск ±10% зашит внутри формул (сверить).

**Как построить:**
1. Таблица: минимум, разница, максимум по каждому методу.
2. Выбрать диапазон → Insert → Stacked Bar, методы по оси Y.
3. Format Data Series: убрать заливку у ряда «минимум», остаётся видна только разница.
4. Добавить подписи нижней и верхней границы.

Подробнее о диапазонах оценки — в [Comps и прецеденты пошагово](#learn/comps).

## Добор кредита: две версии

Условия: операционный поток +10 в год, инвестиции −20, в 5-м и 6-м периодах прочее финансирование +20, касса 10 в начале. Добор = минус остаток, если он отрицателен; погашение = −MIN(излишек; долг на начало). Версии различаются базой процентов.

| | Проценты на начало периода | Проценты на среднее |
|---|---|---|
| **Циклическая ссылка** | нет | есть |
| **Ставка** | 10% × остаток на начало | 10% × среднее(начало; конец) |
| **Долг на конец** | 0 → 10 → 21 → 33,1 → 26,4 → 19,1 | 0 → 10,5 → 22,2 → 35,0 → 28,2 → 20,6 |

Проценты по периодам:

| Период | На начало | На среднее | Разница |
|---|---|---|---|
| **3** | 1,000 | 1,634 | 0,634 |
| **4** | 2,100 | 2,859 | 0,759 |
| **5** | 3,310 | 3,160 | −0,150 |
| **6** | 2,641 | 2,440 | −0,201 |

Версия на среднем остатке точнее, но менее устойчива; для неё в настройках Excel включают итерации. Механика револьвера и циклической ссылки — в [Модель трёх отчётов шаг за шагом](#learn/model-3-otchetov).

## Проверь себя

**1. Почему оси таблицы чувствительности нельзя ссылать на ячейки модели?**
Data Table подставляет значения оси во входную ячейку. Если ось ссылается на модель, подстановка меняет саму ось, и результаты искажаются. Поэтому оси задают числами и держат на том же листе, что и входные ячейки.

**2. Что стоит в левом верхнем углу Data Table и какие поля заполняют в диалоге?**
В углу ссылка на результат (например, IRR). В диалоге Row input — входная ячейка для значений по горизонтали, Column input — для значений по вертикали.

**3. Как собрать переключатель сценариев без макросов?**
Список из трёх значений через Data Validation, формула, превращающая выбор в номер 1–3, и `CHOOSE(номер; база; позитив; негатив)` в каждом драйвере. Строки сценариев лежат отдельным блоком Inputs.

**4. Как ошибку «прибыль = выручка × рост» не заметить при тесте?**
Если рост и маржа равны 10%, результат совпадает с правильным. Ошибка видна только при разных значениях, поэтому каждый вход меняют отдельно и смотрят на выход.

**5. CAPEX 1 000 в год, ставка 20%. Какая амортизация в четвёртый год и в шестой?**
В четвёртый год (2022) списывают по 200 с трёх траншей: 600. С шестого года первый транш списан, и амортизация выходит на устойчивые 1 000.

**6. Чем футбольное поле строят в Excel и зачем нужен столбец «разница»?**
Stacked Bar: ряд «минимум» без заливки, поверх него отрезок длиной «разница = максимум − минимум». Ось складывает ряды, поэтому отрезок начинается у минимума.

**7. Чем отличаются две версии добора кредита и какая точнее?**
Проценты на начало периода не создают циклической ссылки; проценты на средний остаток создают её и требуют итераций. Вторая версия точнее, но менее устойчива: в периоде 3 она даёт 1,634 против 1,000.

**8. Как вычисляется IRR мини-модели инвестора и что показывает CoC?**
IRR считают функцией XIRR по потокам и датам: минус вложения, дивиденды, выход. CoC = (дивиденды + выход) / вложения; в примере 2,45x при IRR 23,7%.
